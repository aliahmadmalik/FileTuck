# Security policy

## Reporting a vulnerability

Use [GitHub private vulnerability reporting](https://github.com/aliahmadmalik/FileTuck/security/advisories/new).
Please do not publish exploit details, private files, credentials, or signing keys
in public issues before the maintainer has had an opportunity to assess the report.

Include the app version, Android version, affected component, expected behavior,
actual behavior, and a minimal reproduction using harmless sample data. Response
times are not guaranteed; this is an independently maintained project.

## Release trust

Download APKs from the official [FileTuck releases](https://github.com/aliahmadmalik/FileTuck/releases).
Each published release includes the APK, its SHA-256 checksum, and the public
signing certificate information. Never send anyone the private signing key.
Updates must retain the same signing identity and use a higher version code.

The latest release is the focus of maintenance. No formal support period or
independent security audit is promised. Signature verification establishes signer
identity and artifact integrity, not the absence of application vulnerabilities.
